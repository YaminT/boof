Boof Runner

Queue the work, review the branch

Every task is a markdown file on disk. The runner hands it to a planner, a developer and a reviewer, driven by coding agents such as Claude Code and Codex, inside a git worktree of its own. When the reviewer approves, you get a branch to review and merge yourself. Drive it from a web UI, a desktop app, the command line, a REST API or MCP.

boof-runner run "Add a rate limiter to the API" --repo /path/to/repo

# drive every project's pending queue
boof-runner run --all

What it does

  • A review gate, not a hope. Observer and reviewer end with a VERDICT line; findings go back to the developer, and only a reviewer approval finishes a task.
  • One worktree per task. Each task runs on its own branch boof-runner/<task-id>. Branches are kept; failed or stopped work is never discarded.
  • Plans with dependencies. A plan is a versioned graph of goals. Sync turns ready goals into tasks and keeps them in line when a goal changes.
  • An API for people and agents. Versioned REST with OpenAPI, ETags and idempotency keys; the same operations as 34 MCP tools; replayable events and signed webhooks.
  • Loopback by default. API keys with scopes and trust levels, a Host guard, a rate limit and an audit log. Treat access to it like access to your shell.
