# Boof Runner 0.3.0 desktop checks

Run this checklist once on macOS and once on Windows. Tick each box and note the OS version and any failure. Installers are unsigned: the macOS builder sets `identity: null` (no signing or notarization), and the Windows builder has no signing configuration. Expect the OS security prompts.

## macOS

- [ ] **Install:** Open the `Boof.Runner-0.3.0-mac-arm64.dmg` or `mac-x64.dmg` matching this Mac; drag Boof Runner to Applications and launch it. If Gatekeeper blocks it, follow the prompt to open this unsigned app. Pass: Boof Runner opens.
- [ ] **First launch:** In the full-screen first-project picker, choose an existing Git repository folder in the native folder dialog. Pass: the Tasks screen opens for that project, and it is not asked again. Data root: `~/Library/Application Support/Boof Runner/data` (key file is alongside it at `~/Library/Application Support/Boof Runner/desktop-ui.key`).
- [ ] **Desktop key:** On startup, confirm the app works with its key encrypted by Electron `safeStorage` in the macOS Keychain. If encryption is unavailable or the stored key cannot be read/decrypted, pass if the app logs the fallback and continues with a browser session the app sets itself; there is no keyless local access. `check:` if macOS displays a Keychain access prompt, note whether allowing or denying it changes startup or the fallback.
- [ ] **Fallback sign-in (no `safeStorage`):** Only if the key could not be stored (see Desktop key). Pass: the window opens signed in with no key prompt. Close the window and reopen it (macOS: click the Dock icon; Windows: relaunch) and pass if it is still signed in. In `<data root>/audit` the app's requests show `auth: "browser-session"`. If the dialog "Boof Runner could not sign in" appears, note the exact text (it names the fix, for example a `chmod go-w` path); pass if the window then shows the sign-in gate and not the Tasks screen.
- [ ] **`auth.mode` required:** Set `auth.mode` to `required` in Settings (or `settings.json`) and relaunch with `safeStorage` unavailable. Pass: the sign-in gate appears and pasting an API key from `boof-runner auth add` signs in.
- [ ] **Mock task:** Open **Settings → Agents**. Set planner, developer, observer and reviewer tools to **mock**, save, then return to Tasks and click **New task**. Enter a title and a prompt such as “Add a comment `desktop mock check` to README.md”; click the create/queue button. Open the task, watch its live log, then its **Changes** tab. Pass: it reaches **done** and the changes tab shows the worktree diff. No agent account is needed.
- [ ] **Plans and settings:** Open **Plans**. Pass: the plans screen loads. Open **Settings** and visit **Project**, **Agents**, **Budgets**, **API keys**, **Automation**, and **Accounts**. Pass: each page loads.
- [ ] **n8n settings:** Open **Settings › Automation**. Pass: it shows the n8n section; **Connect** with a bad URL (for example `http://169.254.169.254`) shows the blocked-address error and saves nothing.
- [ ] **Window navigation guard:** Click an external `https://` link in the app (for example, a docs link). Pass: it opens in the default browser and not in the Boof Runner window.
- [ ] **Claude agent:** In **Settings → Agents**, find `claude-agent`. Pass: it is labeled **(unavailable)** and explains it is not available in the desktop app because the Agent SDK and its Claude Code binary are not included; Claude Code (`claude-code`) is the alternative. Open the Console assistant and try to send a message. Pass: the assistant shows the unavailable line and does not run.
- [ ] **Quit while running:** Queue a task with enough work to remain **running**, then quit Boof Runner once. Pass: the window title or a system notification says `Stopping running task... (quit again to force)` while it drains. After relaunch, inspect the task: it should be **stopped** if shutdown completes within the grace period; if the grace period expires, check whether it is recovered or remains running.
- [ ] **Relaunch:** Quit and open Boof Runner again. Pass: the project, completed task and settings are still present.
- [ ] **Uninstall:** Quit, then remove Boof Runner from Applications. Pass: the app is removed. Its data is not removed automatically; it remains under `~/Library/Application Support/Boof Runner/` (including `data` and the encrypted key). Delete that folder separately only if you want to erase the local data.

## If something fails

Send back the OS and version, installer architecture, checklist item, exact error or screenshot, and the task's status and live log if relevant. Task logs are saved with task data under the OS-specific `data` root above. The app writes startup and quit diagnostics to its process console; the code does not configure a persistent desktop log file. `check:` find whether this release exposes a convenient way to capture that console output on macOS and Windows; if available, send it too. Do not send API keys or other secrets.
