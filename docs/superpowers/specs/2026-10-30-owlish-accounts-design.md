# Owlish: accounts and models, with better-ccflare

Design for the `owlish-accounts` goal (owner decision D2, 2026-10-29: integrate [better-ccflare](https://github.com/tombii/better-ccflare), do not rebuild it; boof controls it and applies the spend rules; check the legal side first; credit it by name). Written 2026-10-30 from the installed package (3.5.105), its docs, the running service on 127.0.0.1:8080 (read-only), and the harness vendors' pages. Sources are linked at the end.

**In one paragraph.** better-ccflare is MIT-licensed, so boof may call it, bundle it or fork it with a notice. The pool itself is the legal exposure, not the software: Anthropic's terms forbid sharing or pooling consumer accounts and restrict subscription OAuth to the unmodified Claude Code CLI, which rules the Claude Agent SDK out for the owner's current (OAuth) accounts. So: boof talks to better-ccflare over HTTP, shows an Accounts page, pauses agents when the pool or a budget runs dry, and keeps the Claude Code CLI as the default harness, adding an Agent SDK adapter for API-key and non-Anthropic accounts.

### 1.3 The provider side: the risk is the pool, not the proxy

The owner decides this; the facts, from the primary pages:

- **Anthropic, Claude Code legal page** ([code.claude.com/docs/en/legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance)): "OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications." "Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication." "Anthropic does not permit third-party developers to [...] route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens." "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK." "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice." Allowed: "an end user [signing] in to the unmodified Claude Code binary with their own Claude subscription." Enforcement was reported on 2026-04-04 ([The Register](https://www.theregister.com/software/2026/02/20/anthropic-clarifies-ban-on-third-party-tool-access-to-claude/5014546)); OpenCode removed Claude Pro/Max login in March on Anthropic's legal request ([issue #48207](https://github.com/anomalyco/opencode/issues/48207)).
- **Anthropic consumer terms** (EEA version, effective 2025-10-08): "You may not share your Account login information, Anthropic API key, or Account credentials with anyone else [...] or make your Account available to anyone else"; you must not be "bypassing any of our systems or protective measures"; and, except through an API key, must not "access the Services through automated or non-human means."
- **better-ccflare's own README**: "Claude OAuth accounts (Claude Pro/Team) are automatically excluded from Codex CLI traffic — Anthropic bans these when used outside Claude CLI."
- **OpenAI**: since DevDay (September 2026) "Sign in with ChatGPT" lets named third-party tools spend a subscriber's own ChatGPT quota, and OpenAI staff put Pi and OpenCode at 10% of Codex traffic ([The New Stack](https://thenewstack.io/sign-in-with-chatgpt/)). OpenAI's terms still forbid sharing credentials; pooling several ChatGPT accounts through one proxy is not something OpenAI has blessed. The OpenAI terms page refused the fetch (403); the owner should read it directly.

Plainly: one person's own subscription behind a local proxy, used through the real Claude Code CLI, is a grey area Anthropic has not pursued; **several consumer accounts pooled to get more than one plan's limits is what Anthropic calls bypassing protective measures, and an account ban is the likely sanction, with no notice.** API-key (console), Bedrock, Vertex, OpenRouter and other pay-per-token accounts carry none of this risk. The owner's pool today is three `claude-oauth` accounts.

Boof's design keeps boof itself clear of the "collect, store, or intermediate credentials" clause: boof never sees provider credentials; sign-in happens in better-ccflare's dashboard through the provider's own flow.

## 2. What better-ccflare does today (3.5.105, from code and docs)

- **A proxy** on port 8080 speaking the Anthropic Messages API (`POST /v1/messages`, legacy `/v1/complete`) and translating OpenAI's Responses API (`POST /v1/responses`, `/v1/responses/compact`) for Codex clients. Clients only set `ANTHROPIC_BASE_URL` (Claude Code) or `OPENAI_BASE_URL=.../v1` (Codex). With client API keys enabled (they are, on this machine: `/api/*` answers "API key required"), clients send `x-api-key: btr-…` or `Authorization: Bearer`; `/health` and `GET /api/sessions/:id/account` are exempt.
- **Accounts** (`--add-account <name> --mode …`): `claude-oauth` (PKCE flow against console.anthropic.com, 5-hour windows and weekly windows tracked), `console` (Anthropic API key), `codex` (OpenAI OAuth, model map read live from chatgpt.com), `vertex-ai`, Bedrock, `openai-compatible`, `anthropic-compatible`, Ollama, OpenRouter, z.ai, Minimax, DeepSeek, xAI, Kilo, Qwen, CodeBuddy. OAuth tokens are refreshed with a 30-minute buffer and stampede guard; they are stored **in plaintext in SQLite** (`docs/security.md`), with optional payload encryption at rest for request bodies.
- **Load balancing**: `session` only (plus `session-drain-soonest[-strict]` and `session-affinity` variants). Round-robin and friends were removed because they "can trigger Claude's anti-abuse systems and result in automatic account bans." Priority 0-100 (lower wins), ties broken by lowest utilisation across windows; sticky for the session duration (18,000,000 ms); auto-fallback to a higher-priority account when its window resets; combos (named fallback chains per model family) when enabled.
- **Rate limits and pauses**: per-account `rate_limited_until`, `rate_limit_reset`, reasons; a 529/5xx is retried once in place then the account is benched; **503 when the whole pool is paused or rate-limited**; manual pause/resume; usage-pause thresholds (pause at N% of the 5-hour or weekly window, auto-resume); monthly token/cost caps per account; `use-extra-usage` admission toggle.
- **Usage and analytics**: per-request tokens, cost, latency, model, account and client key; `GET /api/stats`, `GET /api/requests`, `GET /api/analytics` (filter by account, model, key); alerts (threshold, anomaly, `auth_failure` on a dead refresh token) with webhooks.
- **API**: `GET /health` (200 `ok` / 503 `degraded` or `unhealthy`; `pool.{configured,routable,paused,rate_limited,usage_exhausted,next_available_at}`; `?detail=1` per account when `HEALTH_DETAIL_ENABLED`), `GET /api/accounts` (id, name, provider, priority, paused, tokenStatus, rateLimitStatus, rateLimitReset, sessionInfo, autoFallbackEnabled), `DELETE /api/accounts/:id`, `POST /api/accounts/:id/{pause,resume,priority,auto-fallback,usage-pause-thresholds,force-reset-rate-limit}`, `POST /api/oauth/init|callback`, `GET/POST /api/config/strategy`, `/api/models`, `/api/agents`, `/api/logs/stream`. A React dashboard at `/dashboard`.
- **On this machine**: the npm binary is x86-64 and cannot run on this aarch64 host; `ccflare-tunnel.service` forwards 127.0.0.1:8080 over SSH to the real instance. `/health` now: 3 configured, 1 routable, 2 rate-limited, next available 2026-11-01. The local `better-ccflare.json` only holds strategy and retention settings.

## 3. Integration design

**Settings** (`settings.owlish`, optional): `{ url: "http://127.0.0.1:8080", healthGate: "pause" | "warn" | "off" }`. The client key is a secret, so it lives beside the webhook secrets, not in `settings.json`: `<data>/owlish/secrets.json` (mode 0600, same `WebhookSecretStore` pattern) or `BOOF_OWLISH_API_KEY`. Boof holds no provider credentials.

**Base URLs on the harnesses.** `Pipeline.runStep` passes an `env` into `Tool.run` (the `exec.ts` hook already exists; nothing sets it today):

| Adapter                   | Environment                                                                            | Notes                                                                                                                                                                                  |
| ------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| claude-code, claude-agent | `ANTHROPIC_BASE_URL=<url>`; `ANTHROPIC_AUTH_TOKEN=<key>` only when a key is configured | ccflare's README: with a CLI OAuth login and no proxy key, do not set the token; with keys enforced (this machine) it is required and the CLI's "conflicting auth" warning is cosmetic |
| codex                     | `OPENAI_BASE_URL=<url>/v1`, `OPENAI_API_KEY=<key or dummy-key>`                        | ccflare never routes Codex traffic to Claude OAuth accounts; `127.0.0.1`, not `localhost`                                                                                              |
| opencode                  | provider `options.baseURL` through `OPENCODE_CONFIG_CONTENT`                           | verify in phase 1; OpenCode has no Claude subscription login since 1.3.0                                                                                                               |
| mock                      | none                                                                                   | end-to-end test of the gate without a pool                                                                                                                                             |

The `Tool` interface gains `acceptsPool?: boolean` so the engine knows which roles are routed.

**Owlish client** (`packages/shared/src/owlish.ts` now, `@boof/owlish` at the split): `health()`, `accounts()`, `pause(id)`, `resume(id)`, `setPriority`, `setThresholds`, `spend(filter)` over `/api/analytics`. Ten-second cache for health, errors mapped to one `PoolStatus`: `absent | unreachable | ok | degraded | unhealthy` with the pool counts and `nextAvailableAt`.

**Operations** (`defineOp`, so REST, MCP and CLI come together): `accounts.list` (GET `/accounts`, `boof_list_accounts`, `boof-runner accounts`), `accounts.pause`, `accounts.resume`, `accounts.priority`, `accounts.thresholds` (POST, `settings:write`), `accounts.health` (GET `/accounts/health`). `runner.status` and `runner.overview` gain `pool: PoolStatus`. `settings.update` accepts `owlish`.

**Accounts page** (Settings, sixth page, UI phase 5): the pool banner (status, routable/configured, "next available at"), one row per account (name, provider, priority, window usage, rate-limit state, token status, paused), row actions pause/resume/priority/thresholds, a "Sign in or add an account in the better-ccflare dashboard" link (boof must not run the OAuth flow itself, see 1.3), a provider-terms notice for OAuth accounts, and the credit line. When `settings.owlish` is unset the page says so and offers the setting; the rest of boof is unchanged.

**Spend rules (the "pause the agents to spend wisely" part).** All checks run where budgets already run: between steps and before a task is selected, never inside a running step.

1. _Pool gate_ in `RunnerEngine.selectWithBudget`: when `healthGate` is `pause` and the pool is `degraded`, `unhealthy` or `unreachable`, no task whose roles use a routed tool starts; the reason appears in the Now lane and in `runner.status.pool`; one `runner.pool_exhausted` event per episode (same marker idea as `markBudgetNotified`). Work resumes on its own when health returns (poll every 30 s, or at `next_available_at`). `absent` (no setting) means boof works as today.
2. _Between steps_ in `Pipeline.runStep`: the same gate; a step waiting on the pool is logged as `### Waiting for the account pool (next available 2026-11-01T00:00Z)` and the task stays `running` with a visible wait, up to `retries.poolWaitMs` (default 30 min), then the task fails `pool exhausted` with `onExceed`-style behaviour (`pause` keeps the worktree).
3. _503 from the proxy mid-step_ is already a transient error (`errors.ts` matches `5\d\d`); the retry path now consults the gate before each backoff instead of burning the three attempts.
4. _Budget tie-in_: `BudgetStatus` gains `pool` and the budgets page shows window usage next to dollar scopes. A new optional per-account rule in boof, `reserveWindowPercent` (default 0), pauses selection when every routable account is above that share of its 5-hour or weekly window: this is boof's own "near a budget" rule on top of ccflare's per-account thresholds, which stay the per-account tool. The existing dollar budgets keep working from the step ledger; where a tool's cost is `known: false` (codex), boof may fill it from ccflare's per-request cost by giving each role its own client key (`spend(filter: { apiKey })`), which closes the `usage-ledger-accuracy` gap for routed tools.
5. _Manual_: pausing an account on the Accounts page is immediate (ccflare side); pausing the runner is unchanged.

**Absent or down.** No `settings.owlish`: adapters inherit the environment as now, the Accounts page is a stub, the gate is off. Set but unreachable: treated as `unreachable` under the gate policy, and tool health in Settings says "better-ccflare at <url>: unreachable".

## 4. Harness choice

|                              | Claude Code CLI (current)                                                                                                                                                                                                    | Claude Agent SDK                                                                                                                                         | Codex CLI / SDK                                                                                                                         | OpenCode server                                                                            |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Interrupt and steer mid-step | Kill (SIGTERM) and `--resume` with the new text; partial work kept; `--input-format stream-json` exists, so a live stdin that sends a user message with `priority: "now"` could replace the kill (unverified on the raw CLI) | `interrupt()`, `streamInput()`, user messages with `priority: now/next/later`, `setModel()`, `applyFlagSettings()`, `canUseTool`, hooks, resume and fork | SDK `run()` on a thread, `resumeThread()`; no documented abort or mid-turn message; the app-server protocol has more but is not the SDK | `POST /session/:id/abort` then a new prompt; `prompt_async`; no mid-run message documented |
| Streaming                    | stream-json with partial messages                                                                                                                                                                                            | same events, typed                                                                                                                                       | `runStreamed()` with `item.completed`, `turn.completed`                                                                                 | SSE `/event`                                                                               |
| Usage                        | `result.total_cost_usd` parsed (cost known)                                                                                                                                                                                  | `modelUsage`, `total_cost_usd` per result (known, includes subagents)                                                                                    | `turn.completed.usage` tokens, no cost (known: false)                                                                                   | not documented in the SDK                                                                  |
| Accounts through ccflare     | Claude OAuth, console, Bedrock, Vertex, any Anthropic-format provider                                                                                                                                                        | Same, **but Anthropic says Agent SDK use must be API-key, so no OAuth accounts**                                                                         | Codex OAuth (ChatGPT) and OpenAI-compatible; Claude OAuth excluded by ccflare                                                           | Anthropic-format providers by base URL; no Claude subscription                             |
| Licence                      | Anthropic terms (binary)                                                                                                                                                                                                     | "governed by Anthropic's Commercial Terms of Service" (npm `SEE LICENSE IN README.md`); ~100 MB native binary per platform as optional deps              | Apache-2.0 (`@openai/codex-sdk` 0.166)                                                                                                  | MIT (`@opencode-ai/sdk` 1.19)                                                              |

**Recommendation.** Keep **Claude Code CLI (`claude-code`) as the default role tool**. Reason: the owner's accounts are Claude subscriptions, and the only harness Anthropic names as permitted for them is "the unmodified Claude Code binary". The Agent SDK is the better-controlled harness, and the roadmap was right about that, but Anthropic's legal page assigns it to API-key use; routing SDK traffic over a pool of OAuth accounts is exactly the pattern Anthropic enforces against. So:

- Add the **`claude-agent` adapter** (Agent SDK, `pathToClaudeCodeExecutable` left to the bundled binary, `env` with the base URL) as the controllable harness. It becomes the recommended default for a role when the pool for it holds only console, Bedrock, Vertex or other API-key accounts; the Accounts page says which it is. Concierge (roadmap step 12) uses it with an API key.
- Upgrade `claude-code` steering in place: try the live-stdin path (`--input-format stream-json` plus a `priority: "now"` user message) in a one-day spike; if the raw CLI honours it, `now` steering stops killing the process for the default harness too. If not, kill-and-resume stays, as documented.
- Keep `codex` (gains the base URL, and known cost through ccflare analytics) and `opencode` (base URL only). No Codex SDK adapter now: the SDK adds streaming but no steer.

## 5. Phasing, risks, open questions

**Phases** (each shippable; tests first, mock tool end to end):

1. _Settings and client_ (S): `settings.owlish`, secret store, `OwlishClient` with `health()` and `accounts()`, `runner.status.pool`, credit lines in README and docs. Done when `boof-runner accounts` lists the three accounts.
2. _Base URLs_ (S): `env` through `Tool.run` for claude-code and codex; opencode verified. Done when a mock run records the env and a real planner step appears in ccflare's request log.
3. _Pool gate_ (M): engine and pipeline gates, waits, events, the Now-lane reason. Done: with the tunnel stopped the engine pauses with a visible reason; with it back, work resumes.
4. _Accounts operations and page_ (M): pause/resume/priority/thresholds over REST, MCP, CLI; the Settings page; the ToS notice. Done: pausing from the UI changes `/api/accounts`.
5. _Spend rules_ (M): `reserveWindowPercent`, cost from analytics per client key, budget page tie-in. Done: unit tests for the pause rules; codex steps record `known: true` cost.
6. _`claude-agent` adapter_ (L): streaming input, `interrupt()`, `setModel`, usage from `modelUsage`; the claude-code live-stdin spike beside it. Done: a steered step continues without a process kill.

**Risks.** Account bans for pooled OAuth accounts (owner's call; boof shows the notice and never hides the account kind). The ccflare API is versioned informally and ships several times a week (3.5.105 installed, 3.5.109 on npm); pin the fields boof reads and tolerate unknown ones. Plaintext tokens in ccflare's SQLite on the pool host. The SSH tunnel is a single point of failure, which the gate turns into a pause rather than failed tasks. The live-stdin steer may not work on the raw CLI. `HEALTH_DETAIL_ENABLED` is off by default, so per-account window usage comes from `/api/accounts`, which needs the client key.

**Open questions for the owner (they change what gets built):**

1. Given 1.3, do you keep pooling Claude subscription (OAuth) accounts, or move the pool to console API keys or Bedrock/Vertex? With OAuth, the default harness stays the CLI and the Agent SDK adapter is built only for API-key roles; with keys, `claude-agent` becomes the default and phase 6 moves first.
2. Pool exhausted while a task is mid-pipeline: wait in place (default 30 min, task stays `running`) or fail at once under the `onExceed` rule?
3. Should boof give each role its own ccflare client key so spend is attributed per role in ccflare and codex cost becomes known (needs you to generate keys once in ccflare), or keep one key?
4. Does the Accounts page link to the ccflare dashboard for sign-in only (this design), or embed it in an iframe inside boof?
